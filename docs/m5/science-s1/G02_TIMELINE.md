# G02：持续20次与1–2次的严格时间线

**OPEN / REQUIRES_OWNER_DECISION**。PAPER §3.4.3 印刷p40的“持续超过20个迭代”
和 §3.4.5 p44的1–2迭代/右侧保护k=1或2均保留；SPEC S3只登记分歧。
本轮没有选择正式持续性门槛，也没有实现最终告警。

## 六种时刻

1. 独立 evaluator 的人工退化起始iteration：有事件场景为21；stable为null。
   这是固定合成真值，不是 GPU 实测开始时刻，分析器不接收 evaluator。
2. 每个模型输出 cp 经该前缀 cp−1→retained mapping 转换的原iteration。
   低概率cp也完整保存，不能把全45步的cp移回早期前缀。
3. 首次在当前前缀观测 cpPr>=0.8 的iteration，区别于cp的位置。
4. 首次通过概率、间距、三均值恢复与正向退化过滤的iteration；再分别报告
   A/B强度门槛后的临时候选。这里“临时”指未批准候选，非瞬时故障类别。
5. 各独立20次解释的首次具备相应证据且当前候选仍合格的iteration。
6. 最终告警iteration始终null，NOT_APPROVED/NOT_RUN；final_alert=false。

ADAPTATION 逐前缀代码是固定 `change_detection.py` 的窗口/过滤实验选择。
EXTENSION 新脚本独立重算，不调用正式 detect，不做新的 native fits。
两批×七场景×20重放×45步=12600前缀全部检查，C两批/20重复完全一致；
只因逐前缀内容相同而将630个独特行公开一次，280份覆盖回执分别保留。
完整 [timeline.json](data/timeline.json) 包括所有前缀模型cp、概率合格cp、
过滤后cp、A/B候选、各持续性门槛与final状态；全部均值/概率见 sensitivity.json。
输入文件/前缀/重复 SHA 与无未来对照见 repeat-coverage.json / input-hashes.json。

## EXTENSION：独立候选持续性规则（全部未批准）

令j为本前缀映射后的cp，t为最新原iteration，R为本前缀保留的右侧样本数。
每个规则均须同时满足本前缀概率/间距/恢复/强度；不以过去候选直接产生告警。

| 候选解释 | 精确定义 | 仅就计数的最早时刻（cp固定j） | 风险 |
|---|---|---|---|
| inclusive span | t−j+1>20 | j+20 | 包含cp，共21次；年龄不证明每次均退化或完整保留 |
| elapsed exclusive | t−j>20 | j+21 | 流逝间隔超过20；比含首点解释晚1次 |
| retained samples | R>20 | 无删除且连续时j+20 | 计数与原跨度不同；窗口/离群删除可推迟或使证据消失 |
| consecutive qualified prefixes | 同一原cp、同一A/B方案连续合格次数>20 | 首次合格时刻+20 | 概率/均值波动、漏测、cp漂移都清零；测的是连续判定，非必然连续物理退化 |
| p44 original guard k=1 | t−j>=1 | j+1 | 固定窗口位置规则的原iteration候选解释；压缩时间轴不等价 |
| p44 original guard k=2 | t−j>=2 | j+2 | 多1步右侧支持；仍不能满足p40的>20解释 |

当前临时候选路径没有上述新增门槛（仅已有恢复等过滤）。source-receipts
记录论文位置；新 persistence() 测试明确覆盖20/21/22边界、样本删除、空/非法
及 streak恢复/变点漂移。span只是“足够年龄的观察证据”，不能被写成已经
证实了21次持续退化；未来若选择逐迭代都超过门槛，还需另行定义baseline更新、
缺失点与单点噪声处理。本轮不补成新FLASH事实。

growth20虽然在41步cp年龄满足>20，但当时A比例未越线，首次联合条件在43。
growth20连续方案未达到21次合格，不能从最终45步候选倒推“持续通过”。
recovery在早期被候选保留，后来恢复不能被提前用于过滤早期结果；20次候选
可能阻止该人工例的早期触发，但这不证明降低真实误报的普适性。

要得到与论文唯一可比的检测时延，负责人必须选择持续性的对象（物理退化、
cp年龄、保留样本或连续判定）和计数起点、是否需要k，以及窗口移动时的状态
规则。现有工程证据可支持实现已选择计数规则的单元正确性，不能解决论文冲突。
