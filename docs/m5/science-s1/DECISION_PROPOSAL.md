# 待批准科学决定与 M5-S2 方案

本文件全部候选均 **NOT_APPROVED**，不是已成立的FLASH论文事实。
本轮推荐不关闭任何科学缺口，不启用最终告警，不采纳正式runtime，不启动M6。
证据入口：G01_SEMANTICS、G02_TIMELINE、G13_THRESHOLD与 data/ 完整索引。

## G01

PAPER：点名 Rbeast，给出BOCD run-length表述、30窗口与0.8阈值。
UPSTREAM：固定0.1.25实际BEAST分段trend/模型平均MCMC，cpPr为局部出现率汇总。
ADAPTATION：每前缀独立重拟合/压缩轴/24参数、cpPr>=0.8，并保持 final_alert=false。

| 待选方案 | 语义/误报漏报/时延影响 | 论文可比性和充分证据 |
|---|---|---|
| G01-a：明确采用论文点名库的窗口BEAST候选功能复现 | 历史cp可修订；概率未校准，priors/窗口影响灵敏度；独立拟合CPU成本须后测 | 源码/API/前缀/重复性足以支持工程候选路径；不等同经典BOCD递推或科学有效性PASS |
| G01-b：使用 pointwise cpOccPr 做另一概率诊断 | 对局部汇总与点概率可做敏感性，可能更迟触发或漏掉位置不确定事件；当前数据不是0.8边界实验 | 保留为EXTENSION，不能直接替换论文概率；需另行授权独立对照，不在本轮改正式路径 |
| G01-c：要求严格 run-length BOCD 科学等价 | 当前实现不满足；不能从候选C工程PASS推导可用 | 本轮应停止在争议；负责人另批设计/澄清研究目标，不能静默替换Rbeast |

推荐G01-a作为明确标注的有限功能复现，仍分别描述“论文称BOCD”与“实现为
BEAST窗口重拟合”。负责人需批准模型支持/默认prior、压缩轴、选点概率、
过滤次序与科学声明边界；未批准就保持仅离线证据。收敛/近0.8概率边界、
真实非故障噪声和多cp漂移需后续授权数据验证；任何输入/输出范围/原阈值
失败均停止，不用裁剪/tolerance变PASS。

## G02

PAPER两种表述不能由本数据证明哪个正确。ADAPTATION当前只有恢复过滤和
样本支持，没有批准20次门槛，输出cp年龄>20只是事实。
EXTENSION span含首点、elapsed排首点、retained样本数、连续合格判定、k1/k2
均已独立测试和分别保存；具体首次见G02表。增加>20可推迟 sustained 从22至
41/42，阻止此例recovery的早期候选；也会漏掉短但真实故障。连续判定方案
因概率/阈值/漂移不稳定可无限推迟，即使物理退化持续；k1/k2能更早响应，
但不足以支持p40表述、也不保证误报率。不能因为某规则匹配1–2图表就采纳。

建议负责人显式选择一个主要论文对照口径，其他方案保留敏感性诊断。若选择
p40字面时长，以原iteration含cp计数>20最直接，但须承认“年龄”尚不证明每次
物理退化；若要求连续物理退化，应另批每次测量条件与缺失点处理。若选择
p44右保护，则先选k=1或2及原/压缩坐标，并登记无法同时复现p40字面条件。
本轮没有唯一推荐的科学答案。已有数据足以验证计数实现/影响，不足以批准
论文语义。后测提前声明每阶段起止与墙钟边界；无完整回调/缺失前缀即证据
不足；最终告警仍未实现，后测不能用人工真值帮助在线规则。

## G13

PAPER20%缺分母，故障强度5–85%缺测量换算；ADAPTATION同时保留A/B严格>。
EXTENSION A更接近直接测量迭代时长增长，B与固定工作量1/均值时长吞吐代理
对应。A在时长20–25%增长区间能更早/更频繁产生候选，可能提升轻度响应也
增加噪声误触；B更严格，可能减少候选并漏掉真实21%时长变慢。风险是理论
影响，不是从七fixture取得GPU精确率/召回率。

推荐工程日志主指标用直接可测A，同时保存B及实际吞吐；不据此自行批准A为
论文20%定义。负责人必须选“性能下降”单位/分母，工作量及计时边界；选择B
时明确代理限制。工程边界/12600前缀算术足以支持计算正确性，没有足够证据
决定论文分母。后续真实故障实验必须同时报告注入频率、实际计算退化、A/B、
实测吞吐与强制/自动定位指标；注入真值独立。算术/缺失/恢复异常一律停止
并保留，不能调标签/seed/阈值寻求想要的召回。

1. 负责人先审核PR8与本审计；单独授权M5-S2的runtime用途、隔离部署和CPU回归。
   许可/部署范围明确前不公开wheel；不升级系统或训练栈。只批准工程库修复不
   等于批准检测规则；若仍仅离线诊断，可以保持科学争议OPEN和final_alert=false。
2. 保留正式原wheel、对应.so、完整非缓存venv文件manifest与依赖lock，只读备份
   到新run的私有目录；校验SHA后保留原 `.venv-m5` 原位。禁止先uninstall原库。
   本轮不移动、不拷贝安装、不迁移该环境，只读前后SHA核对。
3. 在新隔离环境部署已有确切C wheel及固定NumPy2.2.6；使用离线/no-deps/锁定
   hash流程。已有wheel缺失/ABI不兼容/新依赖需要即停止，不擅自再编译或下载
   新版本。装前/后记录Python、wheel RECORD、路径与实际加载.so SHA。
4. 新进程确认Python3.12 ABI、package0.1.25+build2c、NumPy版本、实际auto ISA
   AVX512、符号/ABI sizeof96 align32 offsets32/64；保留运行时路径与PID于私有
   日志。参数/seed/阈值仍固定；禁止以版本号或pip安装成功代替加载确认。
5. 运行原API、真正独立full/short前缀精确断言、原Reporter/detection/隐私回归
   以及原P1严格完整后验/候选跨上下文控制。新增部署目标需同模型/实际ISA
   独立确认，不能沿用node-0 PASS推断node-1。任意失配/非法cpOccPr/缺raw/timeout
   即停止采纳，保留失败；不改断言、不切ISA绕过。
6. 只有上述审核与隔离回归完成、负责人明确批准切换指定调用方后，才允许
   将正式调用解释器指向新环境；先确认无当前训练/检测作业仍占用旧路径。
   不直接覆盖原venv，使回滚只需恢复原解释器路径并新进程核对原.so SHA。
   新运行失败先结束本run自身进程、恢复指定调用方、验证原库身份/回归；不
   泛化清理，不把“回滚库”解释成取消已发现科学问题。

要让正式检测产生最终告警，G01的概率/模型语义、G02持续性/k/计数、G13分母/
方向/严格比较、G20回调与传输完成语义必须另获明确批准。替换运行库不自动
解决这些科学选择，也不自动允许M6。计划不包含本轮的安装/迁移/执行。
